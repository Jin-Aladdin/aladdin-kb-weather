== Contact

[cols="1,2",options="header"]
|===
| Topic
| Route

| A claim looks wrong
| Open an issue with the claim identifier and, if you have it, what the source
  actually says. Every claim carries an evidence locator, so a disagreement can
  be settled by looking rather than by arguing.

| A source changed or disappeared
| Open an issue. Do not edit records to match; the update engine and the
  provenance fields exist for exactly this.

| Security issue
| Private vulnerability reporting on this repository. Never a public issue.
  See `SECURITY.adoc`.

| Automation looks stuck
| Check the most recent run of *Update knowledge* and *Automation health*, then
  run *Manual recovery* with `run-all-gates`. `RECOVERY.adoc` walks through it
  and assumes no prior context.
|===

== What a Successor Needs to Know

The pack is data. `claims/`, `sources/`, `evidence/`, `entities/`, `concepts/`
and `relations/` are JSON Lines: one object per line, readable with any text
editor and any JSON parser, with no tooling from this project.

The importers in `scripts/` re-import their sources. Running one against an
unchanged source produces identical files, so an empty diff means nothing
upstream moved. That is the intended way to refresh, and the reason they are
committed rather than run once and forgotten.

`automation/update-policy.yml` declares the live sources. They are capped at
`propose`: a change becomes a pull request, never a direct commit. Raising that
is a deliberate act.

The validation and security gates come from `Jin-Aladdin/aladdin-spec` at a
pinned tag. If that repository ever becomes unreachable, `RECOVERY.adoc`
explains how to vendor the tooling locally. The pack itself needs none of it.
